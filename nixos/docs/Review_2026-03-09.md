# Review of the `pdf2htmlEX‑nixos` project

## Overview

The repository **pdf2htmlEX‑nixos** is a Nix Flake--based fork of the
[`pdf2htmlEX`](https://github.com/pdf2htmlEX/pdf2htmlEX) project. The
fork was created to provide Nix and NixOS users with a reproducible,
hermetically pinned build of the PDF‑to‑HTML converter. Its README
explains that upstream `pdf2htmlEX` relies on internal Poppler classes
such as `CharCodeToUnicode`. These classes were removed in
Poppler 24.10.0+, which broke the upstream project on modern Linux
distributions. This fork therefore locks the build environment to
Poppler 24.02.0 by using `nixpkgs‑legacy` and builds Poppler and
FontForge statically to expose the necessary
symbols[\[1\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/README.md#L5-L9).
Users can run the tool without installing dependencies through the Nix
CLI:

    nix run github:GeniusTechnoMystic/pdf2htmlEX-nixos#pdf2htmlEX -- /path/to/your/document.pdf

### Differences from upstream

The README notes several changes relative to upstream
`pdf2htmlEX`[\[2\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/README.md#L38-L53):

- A number of bug fixes and edge‑case improvements.
- Updated Cairo integration and out‑of‑source builds.
- Improved handling of obscured or partially obscured text, with a
  two‑mode `--correct-text-visibility` flag.
- Added support for transparent text and improved DPI handling (clamping
  the DPI and automatically increasing it when partially obscured text
  is rasterised).

These changes aim to make HTML output more accurate and robust while
maintaining compatibility with the older Poppler ABI.

## Nix Flake structure

### `flake.nix`

The project is managed via a Nix Flake. The `flake.nix` file describes
the project as a "*NixOS 25.11 fork, a hermetic, reproducible
PDF‑to‑HTML
converter*"[\[3\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L2-L5).
It sets `nixConfig` with an extra binary cache
(`https://pdf2htmlex-nixos.cachix.org`) and its public
key[\[4\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L5-L12).
The inputs include two channels:

- `nixpkgs` pinned to the `nixos‑25.11` branch.
- `nixpkgs-legacy` pinned to
  `nixos‑24.11`[\[5\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L14-L19).

Pinning `nixpkgs-legacy` lets the build use Poppler 24.02.0 while still
benefiting from a more recent Nixpkgs for other packages. The
`flake.nix` outputs are generated for each default system using
`flake-utils`. Two packages are provided: `packages.pdf2htmlEX` and
`packages.default` (an
alias)[\[6\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L32-L35).
The package delegates to `nixos/package.nix` via `callPackage`, and a
development shell is defined with common tools and a shell hook that
clearly states the project's cache and
purpose[\[7\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L36-L50).

### `nixos/package.nix`

The Nix derivation builds the `pdf2htmlEX` program from the upstream
source. Key points include:

- The derivation names the package and sets a version suffix
  `v0.18.8.rc1-nixos-25.11`[\[8\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L25-L28).
- `src` points to the repository root, and `sourceRoot` changes into the
  `pdf2htmlEX`
  subdirectory[\[9\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L29-L34).
- `buildInputs` include Poppler, FontForge, Cairo, Freetype, FontConfig,
  JPEG libraries, OpenJPEG, PNG, LibXML2, GLib, Zlib and
  `gettext`[\[10\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L45-L59).
- A custom `cmakeFlags` array enables SVG
  output[\[11\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L61-L64).
- A `postPatch` phase modifies `CMakeLists.txt` to require CMake ≥ 3.5
  and injects pkg‑config lookups for GLib and
  LibXML2[\[12\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L68-L75).
- The lengthy `preConfigure` phase shows how the derivation builds
  static Poppler and FontForge using upstream sources and extensive
  CMake
  flags[\[13\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L79-L173).
  This static build ensures the internal ABI symbols remain available
  and avoids conflicting with the host system.
- Metadata sets the homepage, license (GPL v3+), platforms and
  maintainers[\[14\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L175-L182).

The derivation is well structured and clearly documents why static
builds and pinned dependencies are necessary. The comments emphasise
that the package should never link against newer Poppler versions.

## Maintenance guidelines

The project includes a dedicated `MAINTAINERS.md` file. It instructs
maintainers on how to sync with upstream while preserving the Nix build
logic:

- Add the upstream remote and fetch new
  changes[\[15\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L6-L17).
- Use a "clean‑merge" workflow by creating a sync branch and merging
  `upstream/master`[\[16\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L13-L17).
- If upstream updates CMake or dependencies, maintainers must adjust
  `sed` and `substituteInPlace` commands in `nixos/package.nix`
  accordingly and never update beyond
  Poppler 24.x[\[17\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L21-L24).
- The Nix environment (`nixpkgs-legacy`) should be updated periodically
  via `nix flake update`, but this will not move Poppler or FontForge
  past their safe
  versions[\[18\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L32-L41).
- Instructions for pushing to Cachix manually and via CI/CD are
  provided[\[19\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L43-L54).
- An "AI Agent Guardrails" section reminds maintainers to keep
  `AGENTS.md` updated and to add new C++ dependencies to
  `nixos/package.nix`[\[20\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L58-L61).

The separate `AGENTS.md` file codifies these guardrails for
AI assistants. It explicitly forbids suggesting package managers like
`apt-get` or running build commands directly, mandates that all
dependencies and flags be managed through Nix, and restricts Nix logic
to the `/nixos`
directory[\[21\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/AGENTS.md#L5-L16).
It also warns against updating `nixpkgs-legacy` past Poppler 24.10 and
explains why Poppler and FontForge are built
statically[\[22\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/AGENTS.md#L16-L19).

## Strengths

1. **Reproducible and hermetic build:** By pinning `nixpkgs-legacy` to
   `nixos-24.11` and building Poppler and FontForge statically, the
   project avoids the upstream Poppler API break and ensures
   reproducible builds on any
   machine[\[5\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L14-L19).
2. **Clear documentation:** The README explains why the fork exists and
   provides quick‑start and development
   commands[\[23\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/README.md#L5-L15).
   Maintenance guides and AI guardrails set expectations for future
   contributors[\[20\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L58-L61)[\[24\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/AGENTS.md#L5-L19).
3. **Well‑structured Nix Flake:** `flake.nix` cleanly defines inputs
   and outputs. `nixos/package.nix` isolates packaging logic, making it
   easy to update dependencies or modify the build
   process[\[6\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L32-L35)[\[25\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L25-L59).
4. **Use of binary cache:** The project configures a Cachix binary
   cache and provides instructions for pushing artifacts, reducing
   build times and CI
   workload[\[4\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/flake.nix#L5-L12)[\[19\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/MAINTAINERS.md#L43-L54).
5. **Retention of upstream features:** The fork retains bug fixes and
   enhancements from other pdf2htmlEX forks, improving text visibility,
   transparent text handling and DPI
   management[\[2\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/README.md#L38-L53).

## Areas for improvement and suggestions

- **Automated testing:** The repository does not appear to contain
  automated tests or CI workflows for the Nix build. Introducing CI jobs
  (e.g., GitHub Actions) to build the package across multiple
  architectures and run regression tests would catch breakages early and
  ensure the package remains functional when dependencies are updated.

- **Version naming and release management:** The derivation uses
  `version = "v0.18.8.rc1-nixos-25.11"`[\[8\]](https://github.com/GeniusTechnoMystic/pdf2htmlEX-nixos/blob/nixos-package/nixos/package.nix#L25-L28),
  which embeds the Nix channel version. Formal versioning (e.g., tags or
  releases) would make it easier for users to track changes and upgrade
  intentionally. Creating GitHub releases when significant changes are
  merged would also allow Nix users to reference specific tags rather
  than the mutable branch.

- **Contribution guidelines:** While `MAINTAINERS.md` provides sync
  instructions, there is no `CONTRIBUTING.md` describing how external
  contributors can propose changes, open issues or requests, or how to
  reproduce builds. A clear contribution guide and a code of conduct
  would make the project more welcoming.

- **Nix flake outputs for multiple systems:** The `flake.nix` uses
  `eachDefaultSystem` to build on default systems, but the `devShell`
  uses `pkgs-legacy` (24.11) only. For users on Darwin or other
  platforms, explicit mention of supported systems would help. If the
  package is Linux‑only due to Poppler, documenting this limitation (and
  perhaps gating the output accordingly) would avoid confusion.

- **Upstream changes monitoring:** The project relies on Poppler
  24.02.0. If the upstream pdf2htmlEX community develops a solution for
  the Poppler API change, the fork could reduce its complexity.
  Monitoring upstream progress and documenting whether this fork will
  merge improvements back or eventually deprecate itself would clarify
  its long‑term maintenance plan.

## Conclusion

The `pdf2htmlEX‑nixos` repository thoughtfully adapts the pdf2htmlEX
project for Nix users by creating a hermetic build environment anchored
to a safe Poppler version. Its Nix Flake design, comprehensive
documentation and clear maintenance protocols make it easy to build and
use the tool. Adding automated testing, formal release management and
contributor guidelines would further strengthen the project and help
sustain it over time.
